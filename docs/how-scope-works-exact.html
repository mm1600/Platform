How Scope works — exact

Header by header, field by field, formula by formula: which column each input comes from, what every field of a position, an asset and an Output row is, how every view, metric, check and message is made. Reference tables are generated from the code.

01How to read this

This is the exact companion to "How Scope works": not what Scope does in principle, but which header it reads, which cell it writes, and the formula in between. Reference tables are generated from the code and from one run on the synthetic demo, so they cannot drift from the program. Rule tables follow js/calc/aum.js top to bottom and name the field exactly as the code does.

04The Ownership grid, exactly

  1. Header row = the first row with at least two filled cells; owner column = the first filled column in the rows below it (normally A2). Names across row 1 from B1 are the columns; names down column A from A2 are the rows.
  2. Cell value → share with parseWeight: 1, 0.45, 45%, 9/20, =9/20; a whole number above 1 is a percent (45 → 0.45); text that is none of these → warning, read as 0. A cell on the diagonal (row name = column name) is the row's own share (blank = 1).
  3. A name repeated down the column or across the row: warning, first one used. A row with values but no name: warning, ignored.
  4. The group's row: the row named like the attribution label (default "Group"; "Group weights", "Attribution" also accepted); else a row that is not an investor column, not a look-through row, not the platform total, whose name contains the label or the word group / attribution; else the first such row. Its name becomes the attribution label unless one is set. Its cells = the group's ownership of each investor column (type inference: 1 → Group entity, between → Partly owned, 0 → Third party).
  5. The workbook's own name for the group in Mapping column H ("… Group") becomes the attribution label when no label is set, so it and "Group" are one view.
  6. Cells under the group's column (nobody owns a share of the group): group row empty and column filled → the whole grid is read transposed (warning); both filled → the row wins, differences are listed; such cells are never terms of a view.
  7. A row that is not an investor column, empty, whose column is filled by investor rows: the column is read as its row (information).
  8. Every other row with cells: a row named after an investor column → the view " incl. part in funds" = own column × (diagonal or 1) + Σ cell × column, but only when Mapping column H names that view (any spelling); otherwise the row is reported and not used. Any other name (a region, a name added in the app) → a view of that name = Σ cell × column. A row named like the platform total is ignored.
  9. Terms: a cell's column is an investor column (any of its names: Holdings name, display name, fund name), else another view. "Group" or the platform total as a term is dropped with a warning. A view that refers to itself in a circle: error, the term is ignored; expansion stops at 5 levels.
  10. The look-through register: for every " incl. part in funds" view, each term that is not X's own column is "X holds share of that fund's units"; the fund's type becomes Fund if not set.

07FX, exactly (Calculations CK–CY)

  1. Rates seen: for each currency, every Forex value on its rows and how often (rateCounts); the most frequent is the fallback rate of that currency.
  2. Reference investor: the setting if it names a column; else the first investor column named in Mapping column H (the Output!G8 list mirrors Calculations row 2, whose first column keys the workbook's FX table "EUR"); else the first column of Funding Name. The reference rate of a currency = the Forex on the reference investor's first Holdings row in that currency (CU:CW).
  3. Quote direction: setting, or auto: for every non-EUR row with a reference-currency amount (role nominal_rc: Nominal RC, Amount (EUR), …), test nominal ÷ rate and nominal × rate against it (within 1%); × wins only if it matches more rows and at least 60% of them. ccy_per_eur: EUR = amount ÷ rate; eur_per_ccy: EUR = amount × rate (the rate is inverted once, then always ÷).
  4. Several rates for one currency in Holdings (trade-date rates): information with the range; the reference rate is applied to every row, as the workbook does.
  5. Per row, the rate: currency = EUR → 1, whatever the row's Forex (on a EUR loan in a GBP portfolio the Forex is the EUR→GBP rate; such rows are counted in an information message). Otherwise: FX source "workbook", or the row's portfolio currency is not EUR → the reference rate; none for that currency → the row's own rate with a warning once per currency ("the workbook would convert every X position to 0"). FX source "position" and a EUR portfolio → the row's own rate. Rate blank → the currency's fallback rate with an information message.
  6. FX exception (the older Scope Settings sheet or the app): a row whose currency, investor (column name, loosely, or portfolio code) and, if given, the selected view match uses the exception's rate: a number, or a Hardcoded column holding one rate per asset (matched on the asset's identification ID or holding ID); the column has no rate for the asset → the standard rate, warning.
  7. No usable rate → error, position excluded "no FX rate for X" (the workbook's IFERROR would show 0).
  8. Which currency each amount column is in (setting "Amount columns are in"): quotation currency (÷ the row's rate, the rule), reporting currency (÷ 1), portfolio currency (÷ the portfolio currency's reference rate). Nominal is detected when set to automatic: on non-EUR rows nominal ≈ drawn + unfunded → quotation; nominal × rate ≈ drawn + unfunded → already EUR; ≥ 3 such rows and more than the quotation ones → read as EUR, with a warning (check "Nominal column currency").
  9. nominal_eur = nominal ÷ divisor(nominal); drawn_eur, commitment_eur likewise. Display currency D (EUR unless chosen): nominal_base = nominal_eur × rate(D per EUR); a display currency with no rate → EUR with a warning. Every total, matrix and Output figure uses the _base amounts.

09Views: the exact algorithm

  1. The list: Mapping › Active Assets column H in its order (titles such as "Split Calculations AUM", measure columns such as "Commitment" and " draw" headers left out, with an information message); then the attribution view when the grid or the settings sheet has the group's row; then the grid's views not already listed; then views changed in the app; then the §1 defaults ("Total platform", unless column H already names the platform total). One entry per name whatever its case or spacing; the first spelling wins. Without column H: Total platform and one view per investor column.
  2. Definition precedence per name: app change > the Ownership grid (its row, or the row of the column it looks through under any of its names) > the older Scope Settings sheet > §1 defaults > the attribution label (= the group's weights) > the name is an investor column (× 1, any of its names, never loosely for "incl." names) > a name containing platform / total / commitment / drawn / nominal / exposure = every column. " incl. part in funds" with no definition and X a column or a view = X alone (warning). Anything else: undefined, shows nothing (warning).
  3. A definition is a list of terms [name, weight, text]: a term names an investor column (exactly, any of its names), else a view (exactly), else a loosely named column (an information message says so); the weight is a number or parsed like a grid cell. "Group" and the platform total are never terms.
  4. Terms that are views are expanded to columns (weights multiply, up to 5 levels; a circle is an error); equal columns are merged.
  5. The selected view stays selected even when it shows nothing (warning); only a name that is not a view at all falls back to the platform total.
  6. Register: for each " incl. part in funds" view whose base X is a column or a view with columns, every other term with weight > 0 is a register row (fund, holder X, share); the holder's type and weight come with it.
