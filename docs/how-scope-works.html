How Scope works

Every mechanism, from the four workbook sheets to every page and the PowerPoint pack, in the order the data moves through it. Reference tables are generated from the code itself.

Overview

01The whole machine

Scope is plain HTML, CSS and JavaScript running in your browser: nothing is installed and nothing leaves the laptop. Data moves one way: files → grids → store → one calculation → one result → every page and export. This page follows that path and, part by part, writes down every rule the code applies. What happens when the page opens

  1. index.html loads 39 classic scripts (36 of code, 3 of data) in a fixed order (diagram below). Each one adds itself to a shared Scope object. No build step, no libraries.
  2. store.restore() reads your settings (scope.settings) and correction history (scope.adjustments) from localStorage.
  3. The app asks IndexedDB (database scope, store kv, key sheets) for a saved workbook. It gives up after 1.5 seconds (IndexedDB can stay silent when opened from disk).
  4. Saved workbook found: store.loadSaved() restores the sheets, the rows you added to Mapping and the previous Holdings. Not found: the synthetic demo from data/demo.js is loaded (the demo is never saved).
  5. The sidebar and top bar are drawn, then the page named in the address (#/aum by default).
  6. From then on, any change in the store (a setting, a filter, a new sheet) re-draws the sidebar, top bar and current page; a window resize does the same after 150 ms.

Routing

  • Addresses look like #/<page>/<param>/…, each part URL-encoded. Empty address → #/aum.
  • Each page receives the current result, the store, the settings and helpers. If a page throws, it shows "Module error: …" instead of breaking the app.
  • Pages that need data show "No dataset loaded" when no sheet is loaded; only Data & validation works without data.
  • Hidden routes: #/asset/<code>, #/investor/<name>, #/pivot (redirects to Explorer).

03Reading files: the xlsx and CSV reader

Everything you load becomes a grid: rows[r][c] is Excel row r+1, column c+1, so rows[0][0] is A1. Rows end at their last non-blank cell; a blank cell is null. No business logic happens here: deciding what a column means is the calculation's job.

Inside an .xlsx

  • An .xlsx is a zip. Scope has its own small zip reader: stored and deflate entries (deflate via the browser's DecompressionStream, or Node's zlib in tests).
  • Only the four input tabs, Ownership and an older Scope Settings tab are decompressed; other tabs are listed but never read.
  • Shared strings, inline strings and rich text are read as plain text. Booleans become TRUE / FALSE. Error cells keep their text (#N/A, #REF!).
  • Formulas are not calculated: the value Excel saved with the file is read. A formula cell with no saved value reads as blank and you get a warning ("open and save the workbook in Excel").
  • Number formats are not read, so date cells arrive as Excel serial numbers (e.g. 46203 = 30/06/2026). The calculation converts serials between 20,000 and 80,000 to dates.
  • Workbooks in the 1904 date system are flagged (their serials are 1,462 lower).

CSV and pasted text

  • Encoding: UTF-16 by BOM, else strict UTF-8, else Windows-1252 (Excel's "CSV" on Windows), so £, é and – survive.
  • Delimiter detected on the first line that has one: tab first (Excel copy), then comma, then semicolon (European CSV).
  • Quoted fields may hold commas, line breaks and doubled quotes. Cell text is kept exactly as typed (not trimmed).
  • A paste can start at any cell ("Pasted range starts at C3" adds two blank rows and columns), so cell references match the workbook.

Loading sheets: setSheets

  1. Loading any sheet of yours removes every demo sheet first, so your data never mixes with the demo (a missing sheet shows as missing).
  2. A full load (not "merge") clears the other sheets, the added Mapping rows and the previous Holdings: edits belong to the workbook they were made on.

Manual corrections (adjustments)

On an asset page you can correct a position field (nominal, drawn, commitment, currency, FX rate, ratings, dates, rate type, spread). A reason is required. The correction replaces the imported value inside the calculation; the original is kept and shown in a badge. A new correction of the same field supersedes the old one (kept in history); reverting re-activates the one it superseded. All of it is on Data › Corrections.

aum.js has one entry point, run(). It receives the sheets (with your added Mapping rows), your active corrections, your app changes, the selected view and currency, and optionally the set of Holdings rows that pass the filters. It runs these 16 steps top to bottom every time anything changes and returns one result object. It never touches the page; it runs the same in Node for the tests.

16Step 9 · FX

The rules, exactly

  1. The row's own Forex is a rate to the portfolio's currency, not to EUR: on a EUR loan held in a GBP portfolio it reads 0.855 (EUR→GBP). So a loan quoted in EUR is never converted, whatever the row says, and a non-EUR loan takes the reference investor's rate (a EUR portfolio, so its Forex is a EUR rate); a row's own rate is used only when the reference holds none of that currency, or when "each position's own rate" is chosen and the row's portfolio is in EUR.
  2. Which currency each amount column is in. The rule is the quotation currency (÷ that currency's rate). An extract may carry the nominal already in EUR (reporting currency) or in the portfolio currency; dividing it by the rate would convert it twice. On non-EUR rows nominal = drawn + unfunded in one currency, so Scope detects it: nominal ≈ drawn + unfunded → quotation currency; nominal × rate ≈ drawn + unfunded → already EUR, read as such (warning, check on Data › Checks). Drawn and commitment follow their setting (Data › Formulas).
  3. Quote direction. For every non-EUR position with a reference-currency amount (Nominal RC, Amount (EUR)), Scope tests nominal ÷ rate and nominal × rate against it (within 1%). Auto picks × only if × matches more rows than ÷ and at least 60% of tested rows; otherwise ÷ (the workbook's formula). No RC column: ÷, with a note.
  4. One rate per currency (source "workbook"). The reference investor (setting, else the first investor column named in Mapping column H, which mirrors Calculations row 2 and so the workbook's own FX-table key, else the first column of Funding Name) supplies its first row's rate for each currency; every position in that currency uses it (Calculations CU:CW). A currency the reference investor does not hold: the workbook would show 0; Scope uses each row's own rate and warns once per currency. Source "position": every row's own rate.
  5. Blank rate: taken from other rows of the same currency (note).
  6. Exception (changed in app > sheet > CONFIG): matches currency, investor (column name, loosely, or portfolio code) and, if given, the selected view (exactly). Rate = a number (quoted like the Holdings rates) or a Hardcoded column holding one rate per asset (found by header or row-2 label; missing for an asset → standard rate, warning).
  7. No usable rate → error, position excluded ("the workbook's IFERROR would show 0").
rate per EUR = rate            (units per EUR, ÷ quote)

Input: the register from step 13 (fund, holder, share of units). Output: for every investor, its direct exposure, its exposure through funds, and the total, per asset.

The maths

throughput t(F, A) = Σ over funds G of reach(G → F) × direct(G, A)
                     reach = how much of G's holdings ends up in F through chains of funds (up to 5 levels; G→G = 1)
indirect(X, A)     = Σ over funds F that X holds of share(F, X) × t(F, A)
total(X, A)        = direct(X, A) + indirect(X, A)
external(F)        = t(F) × (1 − Σ listed shares of F)        → shown as "External fund holders"

Because every fund's throughput is split into listed shares plus an external remainder, Σ ultimate holders + external = Σ direct, for every asset and measure (checked; a difference is a warning).

41The PowerPoint writer

  • Slide 13.333 × 7.5 inches (16:9); Arial; one master, one blank layout, a theme. On a template: its slide size (Scope draws on the 13.333 × 7.5 canvas, scaled), its masters, layouts, themes and images.
  • Freeforms: one shape per map country, its outline converted from the map's path (move and line commands) to the slide's own geometry, so each country can be recoloured in PowerPoint.
  • Scatter charts (date axis as Excel serial numbers shown "mmm-yy", markers with their own labels, a line series for a curve) and bubble charts (fixed axes, labels written per bubble). Series are padded to one length because some viewers drop a series shorter than the next one.
  • Shapes: rectangles (optionally rounded), text boxes (paragraphs, runs, bullets, alignment), lines, tables (column widths, header row, zebra rows, bottom borders), charts.
  • Charts: columns, horizontal bars (first category on top), stacked, doughnut. Value labels outside the bars (inside when stacked); the hidden value axis gets 10–18% headroom so labels never clip. Each chart's numbers are also cached in the chart XML and stored in an embedded workbook (Sheet1: categories in A, one column per series), so Edit Data works.
  • Verified by opening and exporting the decks in Microsoft PowerPoint (no repair prompt) and LibreOffice, and by tests that read the package back: every relationship resolves, every part is well formed, chart caches equal the result's figures.

The template. Scope.pptx.readTemplate reads the first slides of your .pptx with everything they use: their layouts, masters (each keeping only the layouts used), themes and images; notes, tags and linked objects are dropped with whatever refers to them, and placeholders holding no text are left out. Slide 1 is the cover, slide 2 the section break, slide 3 the content page (one slide serves every page; two serve cover and section, then content). A text box whose whole text is x is a slot (any case, quotes and brackets allowed: “X”); so is a short line with one x in it, where only the x is replaced and words the value repeats are said once ("REPORTING AS OF “X”" + "REPORTING AS OF 30 JUNE 2026"). Text boxes inside groups are searched too, their place mapped out of the group. On a template nothing is drawn over the cover or section breaks: a role with no slot stays as the template has it. Scope.pptx.slotRoles(page, kind) gives each slot its role: a {token} names it; an x in a title placeholder is the title (the name on a cover), in a subtitle or body placeholder the subtitle (the date on a cover); the other x boxes take the roles left from top to bottom (cover: name, date; section: by font size, largest first: number, title, the lines under it, a placeholder's type saying nothing there; content: header line and title in the top 45%, the source line in the bottom 30%). A slot keeps its own paragraph and run formatting; its text is replaced, lines on separate paragraphs. Page titles are set in the theme's heading font (+mj-lt), or the Title font of Your style. A filled slot is fitted to its text (lines estimated from its font size, its own or its placeholder's, half an em a character, its line and paragraph spacing): a one-line slot whose text would wrap is shrunk to one line; text taller than its box starts at the top and the box grows downward, shrunk only if it would reach the footer. A slot's position is its own, else its layout placeholder's, else its master placeholder's. The content page's free area runs from just under the top slots to just above anything in the bottom 30% of the slide (footer, logo, page number, the source slot), between margins equal to the title's left edge. Each generated slide is a copy of its template slide (shape ids moved to 1000 and up, its images renamed so they never meet Scope's chart ids), slots filled, Scope's shapes on top.
